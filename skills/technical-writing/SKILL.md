# Technical writing

Read `../unslop/SKILL.md` first. Use exact code identifiers and measurable behavior. Prefer short familiar words, active voice, and examples that compile or match the real API. Never invent file paths, performance claims, or commands.

Choose a document's purpose first: a tutorial teaches through verified steps, a how-to accomplishes a task, a reference records complete facts, and an explanation covers rationale and trade-offs. Split mixed purposes rather than forcing them into one narrative.

Begin with what the reader needs to know. Make conditions precede actions. Keep one instruction per sentence, name the actor when it matters, and verify ambiguous pronouns or overloaded terms. State actual preconditions, failure modes and supported platforms. For public API documents, show representative usage, valid inputs, outputs, ownership, error behavior and compatibility constraints.

Do not compress until meaning disappears. When a style rule makes the text harder to understand, preserve the clearer wording.
